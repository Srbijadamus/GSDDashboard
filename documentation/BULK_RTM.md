# Bulk RTM Entry (`/bulk-rtm`, card "Paste & Parse")

**Rule (2026-10-09, permanent):**

> **Bulk RTM Entry = one agent name per line, always for the entry day, the whole day, no time.**

RTM picks a category and pastes a plain list of names. There is no date column and no
time column: the entry applies to the server's local day (Europe/Berlin) as a whole day,
and no time is stored. The card "Manual Entry" and everything else in Pulse is unchanged.

## Why this exists

Before 2026-10-09 the paste parser required `Agent Name HH:MM - HH:MM [optional tag]`
for every category except SL. A list of names — which is what RTM actually has — produced
`Parse error` on every line and saved nothing (live case 2026-10-09: `OFF — Day Off`
9 names → 9 parse errors, 0 saved; `CD — Compensation Day` 3 names → 3 parse errors).
The requirement was never a time: an OFF/CD/AL day is a whole day.

## Rules

| Input | Behaviour |
|---|---|
| `Christian Pastors` | recognised, written for today, whole day |
| `christian   PASTORS` | recognised — case and repeated spaces do not matter |
| `Pastors Christian` | recognised (order-insensitive), shown as "Recognized (name order swapped)" |
| `Christian Pastors 08:00 - 17:00` | name recognised, the time is ignored, the preview notes "Time/date ignored" |
| `Christian Pastors 2026-10-09` | name recognised, the date is ignored, same note |
| `Elena  Schlosse` (typo) | **not** corrected automatically: row says `Name not found`, offers the nearest employees, saves nothing until RTM picks one |
| `Negin BazmiA`, `leksandrina Dencheva` | same — suggestion only, never an automatic correction |
| `08:00 - 17:00` (time only) | no name → `Name not found`, nothing saved |

A row that cannot be recognised is reported per row; **every other row in the same paste
is saved normally**.

## What a row writes, per category

The paste sends the same call the manual surface for that category sends, for the same
day. All of it goes through `Frontend/src/utils/bulkRtmParse.ts`
(`buildBulkRtmWrites`) so the mapping is testable without a browser.

| Category | Endpoint | Stored as | Time |
|---|---|---|---|
| `AL` | `POST /api/shifts/assign/manual` | `ShiftEntries` `ShiftType = AL` | none (null) |
| `OFF` | `POST /api/shifts/assign/manual` | `ShiftEntries` `ShiftType = OFF` | none (null) |
| `CD` | `POST /api/shifts/assign/manual` | `ShiftEntries` `ShiftType = CD` | none (null) |
| `NIGHT` | `POST /api/shifts/assign/manual` | `ShiftEntries` `ShiftType = WORKING` | none (null) |
| `SL` | `POST /api/sickleave` | `SickLeaves` from today (open-ended `2099-12-31`) + synced `ShiftEntries` `SL` | none |
| `BO` | `POST /api/bo-list` (today's list is replaced first) | `BoEntries`, `ShiftStart`/`ShiftEnd` empty | none |
| `WIC` | `POST /api/wic/assignments` | `WicShiftEntries` + `ShiftEntries` `WIC_DUTY` | the **centre's own opening hours** — the paste never carries a time |

`WIC` still needs a location: the per-row override, then the WIC center dropdown, then the
agent's home WIC. A row with none is skipped with a reason (unchanged behaviour).

## Manual is master

`/api/shifts/assign/manual` takes the session KID as the actor, so the paste row is
stamped `ManualChangeBy` / `ManualChangeAt`, `AutoGenerated = false` — exactly like a
manual cell edit in the Shifts grid — and `GSDContext.GuardManualShifts` then refuses to
let any automatic writer change or delete it (verified: an actorless
`POST /api/shifts/assign/bulk` on a pasted row returns **409 Conflict** and writes nothing).

`SL` and `BO` have no manual-marker column in their own tables (`SickLeaves`, `BoEntries`);
the paste writes exactly what the SickLeave page / BO Liste page writes. `SL` days are in
the future-vacation reconciliation *keep* set and the sick-leave sync honours
`PreserveManualShift`, and nothing automatic writes `BoEntries`.

## The day

The day is not entered. The client sends the machine's **local** date
(`localToday()`, deliberately not `toISOString()`, which is UTC and would produce
yesterday between 00:00 and 02:00 Berlin time), and the server falls back to
`DateOnly.FromDateTime(DateTime.Today)` when `shiftDate` is empty
(`ShiftEndpointMapper.WithTodayWhenMissing`) — an explicitly invalid date still fails
closed with 400.

## Tests

* `Frontend && npm run test:bulk-rtm` — parsing, case/whitespace, time/date noise,
  typo → suggestion (never auto-pick), the same typos still auto-correct for the
  Vacations import (which keeps the old behaviour), per-category write targets,
  "only recognised rows are written", local-date handling.
* `dotnet test Backend.Tests --filter FullyQualifiedName~BulkRtmPasteTests` — every
  category writes today/whole day/no time on an in-memory database, the paste row
  equals the Shifts page's manual create for the same category and day, the pasted row
  is protected from the actorless writer, and the server-local date default works.

## Files

* `Frontend/src/pages/BulkRtm.tsx` — the page (preview shows name, recognised employee,
  category, date (today), status).
* `Frontend/src/utils/bulkRtmParse.ts` — parse/resolve/write rules (React-free).
* `Frontend/src/utils/resolveEmployee.ts` — `autoCorrect: false` for the paste:
  a typo stops at "suggest" instead of being corrected.
* `Frontend/src/i18n/locales/{en,de}/common.json` — `bulkRtm.*` (EN/DE only).
* `Backend/BoListService.cs` — `BoEntries.ShiftStart/ShiftEnd` may arrive empty
  (stored as `''`; the columns are `NOT NULL nvarchar(10)`, no schema change).
* `Backend/ShiftService.cs` — `/assign/manual` and `/assign/bulk` default a missing
  `shiftDate` to the server's local today.
* `Backend.Tests/BulkRtmPasteTests.cs` — the backend acceptance tests.
