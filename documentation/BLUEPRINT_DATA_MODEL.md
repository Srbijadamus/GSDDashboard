# GSDDashboard — Data Model Reference (Section 3)

**Part of the Project Blueprint.** See [PROJECT_BLUEPRINT.md](./PROJECT_BLUEPRINT.md) for the index.

This document describes every database table: columns, types, meanings, who writes each, who reads it.

---

## Database

SQL Server Express (`localhost\SQLEXPRESS`, database `GSDDashboard`, Windows auth).
EF Core 8 manages schema via `GSDContext`. Several tables exist only as inline `CREATE TABLE` DDL in `Program.cs` (idempotent, run on every startup). There are no EF Core migrations — the startup DDL blocks are the migration strategy.

## 2. `ShiftEntries`

The master shift plan. Written by: `import_shifts.py` (Excel import), `ShiftSyncService` (auto-sync from sick leave / vacation creates), and the REST API (`POST /api/wic/shifts`, `PATCH /api/shifts/{id}`).
Read by: almost every service.

| Column | Type | Description |
|---|---|---|
| Id | INT PK IDENTITY | Surrogate key |
| EmployeeId | NVARCHAR(20) NOT NULL | Agent identifier |
| ShiftDate | DATE NOT NULL | Calendar date |
| RawValue | NVARCHAR(200) | Original cell value from Excel import |
| ShiftType | NVARCHAR(20) NOT NULL DEFAULT 'EMPTY' | See table below |
| ShiftStart | NVARCHAR(10) | Shift start "HH:mm". Null for leave/off types. |
| ShiftEnd | NVARCHAR(10) | Shift end "HH:mm" |
| IsWicDuty | BIT NOT NULL DEFAULT 0 | **FOSSIL.** Was used to mark WIC duty before `ShiftType=WIC_DUTY` was introduced. Startup migration clears any corrupt `IsWicDuty=1` rows where `ShiftType != 'WIC_DUTY'`. Do not rely on this flag — always use `ShiftType`. |
| SourceSheet | NVARCHAR(20) | Import source: "EXCEL", "AL_IMPORT", "MANUAL", "SickLeave", "Vacation", "ASSIGN" |
| AgentTask | NVARCHAR(20) | Badge shown on the shift cell in the Shifts page UI (e.g. a WIC location abbreviation). Written by the assignment endpoint. |
| LocationId | NVARCHAR(50) | WIC `LocationCode` set when creating a WIC_DUTY row via REST API |
| AssignmentStatus | NVARCHAR(20) | Not documented |
| AutoGenerated | BIT NOT NULL DEFAULT 0 | True when the row was written by `ShiftSyncService` (not by a human import) |
| SourceModule | NVARCHAR(50) | Last writer: "SickLeave", "Vacation", "MANUAL", "ASSIGN" |
| SourceId | INT | ID of the source record (e.g. `SickLeaves.Id`) used by `ShiftSyncService.RevertSickLeaveAsync()` to find and revert the row |
| PreviousStatus | NVARCHAR(50) | The `ShiftType` before auto-override. Populated by `ShiftSyncService` so revert can restore the original value. |

**Unique constraints:**
- `UQ_ShiftEntries_EmpDateSheet` on (EmployeeId, ShiftDate, SourceSheet)
- `UQ_ShiftEntries_EmpDateType` on (EmployeeId, ShiftDate, ShiftType)

**Duplicate resolution:** An agent can have two rows for the same date from different imports (e.g. WORKING from Excel + AL from AL_IMPORT). `ShiftDuplicateResolver.BestShiftEntry()` picks the row with the highest Id (latest write). All bulk services use this resolver.

### ShiftType values

| Value | Meaning | Paid |
|---|---|---|
| WORKING | Normal GSD shift | yes |
| WIC_DUTY | Agent is on WIC duty travel | yes |
| AL | Annual leave | yes |
| HALF_AL | Half-day annual leave | yes |
| SL | Sick leave | yes |
| UL | Unpaid leave | no |
| OFF | Day off | — |
| OFF_WEEKEND | Weekend off | — |
| PH | Public holiday (national) | — |
| LPH | Local/regional public holiday | — |
| CD | Compensation day | — |
| OL | Other leave | no |
| CO | Compensation off | — |
| TRAINING | Agent on formal training | yes |
| RESIGNED | Agent has resigned | — |
| EMPTY | No shift data | — |

`ShiftTypes.UnpaidTypes = { UL, OL }`. All other populated types are treated as paid.

## 3. `WicShiftEntries`

One row per agent per WIC day (and per WIC location if an agent covers two in one day). Populated by `import_shifts.py` and the assignment REST endpoint.

| Column | Type | Description |
|---|---|---|
| Id | INT PK IDENTITY | Surrogate key |
| EmployeeId | NVARCHAR(20) NOT NULL | Agent identifier |
| ShiftDate | DATE NOT NULL | Calendar date |
| DayOfWeek | NVARCHAR(10) | Day name string (e.g. "Monday") |
| SupportLocation | NVARCHAR(200) | WIC display name as it appears in the Excel file. **No FK to WicLocations.** All matching uses `WicLocationMatcher.MatchesSupportLocation()`. May contain Windows-1252 double-encoded values (repaired in the matcher). |
| WicOpeningHours | NVARCHAR(50) | Opening hours string from the Excel import (e.g. "08:00-17:00") |
| WorkingShift | NVARCHAR(50) | Agent's working shift at the WIC (e.g. "07:30-15:00") |
| IsOnSite | BIT NOT NULL DEFAULT 0 | True when the agent is physically present at the WIC. This is the primary flag used by all coverage services. |
| IsGSDDay | BIT NOT NULL DEFAULT 0 | True when a previously on-site WIC assignment was moved to GSD backlog duty for that day. Set to `true` by `POST /api/wic/move-to-gsd` on the agent's prior on-site row (alongside `IsOnSite=0`); set to `false` on rows created by the assignment REST endpoint. Historical Excel-import values may also be non-zero. Not read by any coverage service — informational history only, exported to Excel as the "GSD Day" column. |
| IsOffDay | BIT NOT NULL DEFAULT 0 | **FOSSIL.** Previously used for off days. No longer written or relied upon. |
| Task | NVARCHAR(20) DEFAULT 'WIC' | Task badge: "WIC", "Voice", "Backlog", "SL", "AL", etc. Editable from the WicSchedule page. |
| LocationCode | NVARCHAR(50) | `WicLocations.LocationCode` — set only when row is created via the REST API (not by Excel import). Null on imported rows. |

**Unique constraint:** `UQ_WicShift_EmpDateLoc` on (EmployeeId, ShiftDate, SupportLocation).

**Ghost rows:** A partial-write bug (referred to as the "B1 transaction bug") can leave rows where `SupportLocation IS NULL` while a valid sibling row exists for the same (EmployeeId, ShiftDate). These are cleaned by `POST /api/admin/cleanup-wic-orphans`. Do not add `SupportLocation IS NOT NULL` filters in new code — use the cleanup endpoint instead.

**WIC vs VWIC collision:** Checking whether a `ShiftType` is WIC-related using a substring match on "wic" will also match "vwic". Always compare against `ShiftTypes.WicDuty` ("WIC_DUTY") exactly.

| Coordinates | NVARCHAR(50) | "lat,lon" (e.g. "51.45,7.01"). Used by SubstitutionService haversine distance calculation. |
| MinAgentsRequired | INT | Minimum agents required. Null = use default (1). Can be overridden per-day in `WicOpeningHours.MinRequired`. |
| Bundesland | NVARCHAR(50) | German federal state. Used for regional public holiday matching. |
| LocationCodeLegacy | NVARCHAR(50) | Old-format code (e.g. "DE_Dortmund"). Bridges old `WicAgentAssignments` rows that use the old code format. |

| IsNpp | BIT NOT NULL DEFAULT 0 | True for Nuclear Power Plant sites. The assignment API warns if the agent lacks `NppQualified = true`. |
| OpeningDay | NVARCHAR(200) | Human-readable opening day description |

## 6. `WicOpeningHours`

Per-location, per-day-of-week opening hours with time-versioning. Written by: admin endpoints.
Read by: ForecastService, SubstitutionService, WicCardsService, WicShiftService.

| Column | Type | Description |
|---|---|---|
| Id | INT PK IDENTITY | Surrogate key |
| LocationCode | NVARCHAR(50) NOT NULL | WIC location code |
| DayOfWeek | INT NOT NULL | 0=Sunday … 6=Saturday (.NET `DayOfWeek` convention) |
| OpenTime | NVARCHAR(10) | Opening time "HH:mm" |
| CloseTime | NVARCHAR(10) | Closing time "HH:mm" |
| OpenTime2 | NVARCHAR(10) | Second interval open (split-hours locations) |
| CloseTime2 | NVARCHAR(10) | Second interval close |
| IsClosed | BIT NOT NULL DEFAULT 0 | True when the location is closed that day of the week |
| RawSchedule | NVARCHAR(100) | Original schedule string from import |
| EffectiveFrom | DATE | The earliest date this row applies. Null = applies from the beginning. `WicHoursResolver.Resolve()` picks the row with the latest `EffectiveFrom <= queryDate`. |
| ChangeNote | NVARCHAR(500) | Reason for the schedule change |
| MinRequired | INT | Per-day override of `WicLocations.MinAgentsRequired`. Null = use location default. |

**Resolution rule:** Multiple rows can exist for the same (LocationCode, DayOfWeek). The one with the greatest `EffectiveFrom` that is still `<= date` wins. If none has `EffectiveFrom`, the single null row applies.

## 8. `SickLeaves`

Sick leave records. Written by: the `/api/sickleave` REST endpoints and PS1 import scripts.
Read by: AvailabilityResolver, ForecastService, SubstitutionService, DashboardService, SickLeaveService.

| Column | Type | Description |
|---|---|---|
| Id | INT PK IDENTITY | Surrogate key |
| EmployeeId | NVARCHAR(20) | Agent identifier. Nullable for historical import compatibility. |
| FirstName | NVARCHAR(100) | Denormalised first name |
| LastName | NVARCHAR(100) | Denormalised last name |
| FullName | (not mapped) | Computed property: `(FirstName + " " + LastName).Trim()` |
| TeamLeadName | NVARCHAR(200) | Team lead name (denormalised) |
| FirstDay | DATE NOT NULL | First day of sick leave |
| LastDay | DATE NOT NULL | Last day. **Sentinel value `2099-12-31` means the leave is still open-ended** (agent has not returned yet). The SickLeaveService writes this value when no end date is known. |
| DurationDays | INT | Calendar days duration |
| LeaveType | NVARCHAR(10) | "SL" = self sick, "Child" = child sick, others not documented |
| ChildName | NVARCHAR(200) | Child's name when `LeaveType = "Child"` |
| Comments | NVARCHAR(500) | Free-text notes |
| SourceSheet | NVARCHAR(50) | "UI" when created via the REST API; import sheet name otherwise |
| CreatedAt | DATETIME2 NOT NULL | Creation timestamp |

**Unique constraints:**
- `UQ_SickLeaves_EmpFirstDay` on (EmployeeId, FirstDay)
- `UQ_SickLeaves_EmployeeId_Sentinel` — filtered unique: only one row per EmployeeId where `LastDay = '2099-12-31'`. Guarantees at most one open-ended record per agent.

**Langzeitkrank:** Sick leave of 21 or more calendar days is classified as "long-term sick" (Langzeitkrank) in the UI.

**Cross-check with ShiftEntries:** When a SickLeave record is created, `ShiftSyncService.SyncSickLeaveAsync()` writes SL-type `ShiftEntries` for all weekdays in the range (capped at 90 days ahead to avoid flooding the table from open-ended records). On deletion, `RevertSickLeaveAsync()` restores the previous ShiftType.

## Cross-Table Join Patterns

Because there are no DB-level FK constraints, all joins happen in application code:

```
ShiftEntries.EmployeeId  →  Employees.EmployeeId
WicShiftEntries.EmployeeId  →  Employees.EmployeeId
```
