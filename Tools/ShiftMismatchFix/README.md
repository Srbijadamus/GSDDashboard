# ShiftMismatchFix — SHIFT_MISMATCH repair (2026-10-14)

One-off, scripted repair of `ShiftEntries` `WIC_DUTY` rows written by an automatic
`SYSTEM_*` roster batch that stored **the centre's opening hours** as the agent's own
shift (the historical writer that `ROSTER_AND_SCHEDULING.md` §4.1 records as removed:
a WIC request without explicit times used to fall back to the centre window).

## Files

| File | What it does |
|---|---|
| `Fix-ShiftMismatch.ps1` | Dry run (default) = SELECT only, writes plan/report/CSV. `-Apply` = backup + one transaction with a per-row guard. |
| `Verify-ShiftMismatchPostChecks.ps1` | Post-write checks 2/3/1/4/5/6 (overlaps, AL/SL, dry run, Shift Plan→WIC sync, HR export, health + WIC routes local and tunnel). |
| `REPORT-20261014.txt` | The report of the run actually applied on 2026-10-14. |

## Rules implemented

Scope: `ShiftEntries`, `ShiftType='WIC_DUTY'`, `ShiftDate` 2026-10-15 .. 2027-02-28.

A row is repaired only when **all** hold:

- **a)** `SourceModule='Roster'` AND `AutoGenerated=1` AND `ManualChangeBy` empty AND
  `RosterBatches.CreatedByKid LIKE 'SYSTEM_*'` (`SYSTEM_WICFIX`, `SYSTEM_BACKUPFIX`,
  `SYSTEM_EXT2027`, …).
- **b)** `ShiftStart-ShiftEnd` is **exactly** the centre's working window for that date
  (the resolved `WicOpeningHours` primary interval `OpenTime-CloseTime`, or the
  resolver's `DutyWindow`) — the trace of the bug.
- **c)** the agent has a clear usual shift **for that weekday**: the most frequent
  `ShiftStart-ShiftEnd` over the agent's own manual rows (`ManualChangeBy` set) and
  `WORKING` rows of the **8 weeks (56 days) ending on the server day**, restricted to the
  same `DayOfWeek`, with **>= 3 occurrences and >= 60 % share**. Not enough data for that
  weekday → the same rule over all days of the window. Still nothing → **not touched**
  (RTM list).

Repair:

- `ShiftEntries.ShiftStart/ShiftEnd` = the usual shift (c);
  `ManualChangeBy/At/Note` = the repair's provenance (`S69307`, never the RTM KID `S60028`).
- `WicShiftEntries.WorkingShift` = intersection of the new shift with the centre's working
  intervals for that date (first overlap start .. last overlap end, the codebase's
  spanning convention). Empty intersection → not changed, RTM list.

Never touched: manually changed rows, `AL/SL/OFF/PH` and every other absence, rows with no
clear usual shift, today and past days.

## Notes

- The baseline window is anchored on the server day ("u poslednjih 8 nedelja"), which is
  also the definition used by `Tools/Backfill-WicDutyCandidates.ps1`. `-BaselineAnchor Row`
  switches to the 8 weeks before each row's own date; it produces a much smaller repair set
  and is kept only as a sensitivity variant.
- PowerShell gotcha found while writing this: `[int]$ts.TotalHours` **rounds** (`[int]7.5`
  = 8), which silently shifts every half-hour time. Always use `$ts.Hours`.
- `WicLocationMatcher.RepairDoubleEncoding` repairs a value only when it actually contains
  the Windows-1252 marker `Ã`; a generic UTF8/1252 round-trip corrupts a correct
  `Saarbrücken`.
- The apply run: 1878 `ShiftEntries` rows + 421 `WicShiftEntries.WorkingShift` values, one
  transaction, 0 guard skips, backup + SHA256 + `rollback.sql` (not executed) under
  `C:\ProgramData\PulseRollback\shift-fix-20261014-083131\`.

## Usage

```powershell
# dry run (no writes) - writes plan + report + CSV under .tmp-shiftfix
pwsh -File Tools\ShiftMismatchFix\Fix-ShiftMismatch.ps1

# the only writing mode; refuses unless the plan row count matches
pwsh -File Tools\ShiftMismatchFix\Fix-ShiftMismatch.ps1 -Apply -ExpectedFixCount <n>

# post-write checks
pwsh -File Tools\ShiftMismatchFix\Verify-ShiftMismatchPostChecks.ps1
```
